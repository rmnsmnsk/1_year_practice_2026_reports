\section{Введение}

Работа выполнялась в рамках учебной практики второго семестра первого курса на кафедре системного программирования. Разреженные матрицы, в которых большинство элементов равны нулю, широко применяются в вычислительной математике, анализе графов и машинном обучении. Хранение таких матриц в плотном виде приводит к нерациональному использованию памяти и вычислительных ресурсов. Для работы с разреженными матрицами разработаны специализированные форматы хранения, такие как COO (Coordinate List~--- список координат) и CSC (Compressed Sparse Column~--- сжатое разреженное хранение по столбцам), а также оптимизированные библиотеки, например CSparse, входящая в состав SuiteSparse~--- набора библиотек для работы с разреженными структурами данных.

\section{Цель работы}

Целью работы является сравнительный анализ производительности двух подходов к хранению и обработке разреженных матриц.
\begin{itemize}
    \item самостоятельной реализации на языке~C с использованием формата COO;
    \item эталонной библиотеки CSparse (SuiteSparse), использующей формат CSC.
\end{itemize}

\section{Задачи работы}

Для достижения поставленной цели были определены следующие задачи.
\begin{enumerate}
    \item реализовать библиотеку для работы с разреженными матрицами в формате COO, включающую операции умножения матриц и умножения матрицы на вектор;
    \item подготовить набор тестовых матриц из открытой коллекции SuiteSparse Matrix Collection;
    \item разработать программу для измерения времени выполнения операций для обеих реализаций;
    \item провести сравнительные измерения производительности и проанализировать полученные результаты;
    \item сформулировать выводы о применимости каждого подхода в зависимости от требований к производительности и сложности реализации.
\end{enumerate}

\section{Обзор форматов хранения разреженных матриц}

Разреженные матрицы могут храниться в различных форматах. Формат COO представляет матрицу тремя одномерными массивами: индексы строк, индексы столбцов и значения ненулевых элементов. Данный формат интуитивно понятен и прост в реализации, однако не обеспечивает эффективного доступа к элементам по столбцам или строкам.

Альтернативный подход представлен в библиотеке CSparse, где используется формат CSC. В этом формате ненулевые элементы хранятся по столбцам, что обеспечивает быстрый доступ к элементам конкретного столбца и эффективное выполнение операций, требующих обхода по столбцам.

\section{Описание решения}

Сравнение проводилось между двумя подходами к представлению разреженных матриц.

\subsection{Собственная реализация (формат COO)}

Реализация на языке~C использует формата COO с тремя одномерными массивами. Управление памятью осуществляется вручную через функции \texttt{malloc} и \texttt{free} стандартной библиотеки~C.

Перед выполнением умножения матриц входные данные сортируются по строкам, а внутри строк~--- по столбцам с использованием сортировки выбором. Сама операция умножения реализована прямым перебором всех пар ненулевых элементов: для каждой пары проверяется совпадение индексов, при совпадении вычисляется произведение, после чего выполняется линейный поиск в результирующем массиве для проверки, не был ли уже добавлен элемент с такими координатами. Если элемент найден, значение суммируется, иначе добавляется новый элемент.

Умножение матрицы на вектор выполняется с использованием плотного промежуточного массива: вектор разворачивается в плотную форму, затем выполняется накопление результатов в плотном массиве, который в конце преобразуется обратно в разреженный формат COO. Аналогичным образом реализовано умножение вектора-строки на матрицу.

Такой подход обеспечивает простоту реализации и наглядность кода, однако сопровождается значительными накладными расходами: квадратичная сортировка, линейный поиск при добавлении элементов и многократные преобразования между разреженным и плотным представлениями создают дополнительную вычислительную нагрузку.

\subsection{Библиотека CSparse}

Использование эталонной библиотеки CSparse осуществлялось без модификаций. Библиотека использует формат CSC и оптимизированные алгоритмы умножения матриц, которые минимизируют количество операций с памятью и переборов элементов.

\section{Эксперименты}

\subsection{Методика измерений}

Для проведения сравнительного анализа были использованы реальные матрицы из открытой коллекции SuiteSparse Matrix Collection: \texttt{dolphins} ($62 \times 62$, 159 ненулевых элементов), \texttt{lesmis} ($77 \times 77$, 254 ненулевых), \texttt{polbooks} ($105 \times 105$, 441 ненулевых), \texttt{football} ($115 \times 115$, 613 ненулевых), \texttt{celegansneural} ($297 \times 297$, 2345 ненулевых), \texttt{netscience} ($1589 \times 1589$, 2742 ненулевых). Все матрицы являются квадратными и симметричными.

Рассматривались две операции.
\begin{itemize}
    \item умножение матрицы на саму себя ($A \times A$);
    \item умножение матрицы на вектор ($A \times x$).
\end{itemize}

Измерения времени выполнялись с использованием стандартной функции \texttt{clock()} из библиотеки \texttt{<time.h>}, которая позволяет оценить процессорное время, затраченное на выполнение операции.

Характеристики вычислительной системы, на которой проводились измерения.
\begin{itemize}
    \item операционная система: Ubuntu~24.04 LTS;
    \item ядро: Linux~6.17.0-35-generic (x86\_64);
    \item процессор: 13th~Gen Intel Core i5-13420H (12~ядер, частота до 4,6~ГГц);
    \item оперативная память: 16~ГБ;
    \item компилятор: GCC (стандартные флаги оптимизации \texttt{-O2}).
\end{itemize}

\subsection{Анализ результатов}

Разница в производительности обусловлена несколькими факторами.

\begin{itemize}

\item при умножении матриц в COO выполняется предварительная сортировка элементов для упорядочивания данных, что само по себе требует дополнительного времени. Затем происходит полный перебор всех пар ненулевых элементов обеих матриц. Для каждого совпадения индексов выполняется линейный поиск по уже накопленному массиву результата, чтобы проверить, не добавлялся ли уже элемент с такими координатами. По мере заполнения результата время этого поиска возрастает. CSparse использует специализированные алгоритмы, которые избегают таких линейных поисков за счёт эффективной структуры данных.

\item при умножении матрицы на вектор в COO разреженный вектор сначала разворачивается в плотный массив, затем создаётся временный массив для накопления результата, который в конце снова упаковывается в разреженный формат COO. Эти многократные преобразования создают существенные накладные расходы.

\item для умножения матрицы на вектор разница в производительности менее выражена, так как сама операция проще: не требуется перебор пар элементов и поиск дубликатов.

\end{itemize}

\subsection{Выводы по экспериментам}

На основе проведённых измерений можно сделать следующие выводы.
\begin{itemize}
    \item на идентичных данных библиотека CSparse показывает значительно меньшее время выполнения операций по сравнению с самостоятельной реализацией COO;
    \item для умножения матриц разница варьируется от~18 до~817~раз, для умножения матрицы на вектор~--- от~2 до~8~раз в зависимости от размера матрицы;
    \item собственная реализация на~C с форматом COO проста в реализации и понимании, но существенно уступает оптимизированной библиотеке CSparse в производительности;
    \item CSparse использует эффективные алгоритмы и структуры данных, что делает его предпочтительным выбором для задач, критичных к производительности;
    \item одномерные форматы хранения обеспечивают простоту реализации, но работают медленнее специализированных библиотечных решений.
\end{itemize}

В ходе выполнения работы были получены следующие результаты.
\begin{itemize}
    \item реализована библиотека разреженной линейной алгебры на языке~C в формате COO с операциями умножения матриц и умножения матрицы на вектор;
    \item проведено сравнительное измерение производительности с использованием эталонной библиотеки CSparse на реальных матрицах из коллекции SuiteSparse Matrix Collection;
    \item продемонстрированы компромиссы между двумя подходами: самостоятельная реализация обеспечивает простоту и наглядность кода, но уступает в производительности оптимизированной библиотеке;
    \item выявлено, что преимущество CSparse наиболее заметно при более сложных операциях, таких как умножение матриц, где ускорение достигает сотен раз.
\end{itemize}
