\section{Введение}

Разреженные матрицы, где большинство элементов нулевые, возникают в задачах вычислительной математики, анализа графов и машинного обучения. Хранение таких матриц в полном виде неэффективно, поэтому разработаны специализированные форматы и библиотеки для работы с ними.

\section{Цель работы}

\text{Целью работы является} анализ компромиссов между двумя подходами к хранению и обработке разреженных матриц: самостоятельной императивной реализацией на языке C с форматом COO (Coordinate List) и эталонной библиотекой CSparse (SuiteSparse), реализованной на языке C с использованием формата CSC (Compressed Sparse Column).

\section{Обзор}

Разреженные матрицы могут храниться в различных форматах. Формат COO (Coordinate List) представляет матрицу тремя плоскими массивами: индексы строк, индексы столбцов и значения ненулевых элементов. Альтернативный подход представлен в библиотеке CSparse (часть SuiteSparse), где используется формат CSC (Compressed Sparse Column), обеспечивающий более эффективный доступ к столбцам матрицы.

\section{Описание предлагаемого решения}

Сравнение проводилось между двумя подходами к представлению разреженных матриц.

\begin{itemize}
    \item{Собственная реализация (COO Format)}. Реализация на языке C, использующая формат Coordinate List (COO) с тремя плоскими массивами (индексы строк, индексы столбцов, значения). Управление памятью осуществляется вручную через \texttt{malloc}/\texttt{free}. Умножение матриц реализовано через вложенные циклы с линейным поиском для суммирования элементов.

    \item{CSparse (SuiteSparse)}. Использование эталонной библиотеки CSparse, применяемой без модификаций. Библиотека использует формат CSC и оптимизированные алгоритмы умножения матриц.
\end{itemize}

\section{Эксперименты}

\subsection{Методика измерений}

\begin{itemize}
    \item \text{Были использованы} реальные матрицы из коллекции SuiteSparse Matrix Collection: \texttt{dolphins} (62×62, 159 ненулевых элементов), \texttt{lesmis} (77×77, 254 ненулевых), \texttt{polbooks} (105×105, 441 ненулевых), \texttt{football} (115×115, 613 ненулевых), \texttt{celegansneural} (297×297, 2345 ненулевых), \texttt{netscience} (1589×1589, 2742 ненулевых). Все матрицы являются квадратными и симметричными.
    \item \text{Рассматривалась} операция умножения матрицы на саму себя ($A \times A$).
    \item \text{Инструменты измерения}. POSIX-таймер \texttt{clock()} из библиотеки \texttt{<time.h>} с точностью до микросекунд. Для каждой матрицы выполнялся один запуск.
\end{itemize}

\subsection{Анализ результатов}

Разница в производительности обусловлена несколькими факторами:

\begin{itemize}
    \item \text{Алгоритмическая сложность}. В реализации COO используется квадратичный алгоритм с вложенными циклами и линейным поиском для суммирования элементов, что даёт сложность $O(nnz^2)$ в худшем случае. CSparse использует оптимизированные алгоритмы умножения разреженных матриц на основе формата CSC.

    \item \text{Структура данных}. Формат CSC обеспечивает эффективный доступ к столбцам матрицы, что критически важно для умножения. Формат COO требует дополнительных операций для группировки элементов по столбцам.

    \item \text{Управление памятью}. Реализация COO выполняет множественные выделения памяти и сортировку элементов пузырьковым методом, что создаёт дополнительные накладные расходы. CSparse использует оптимизированные стратегии выделения памяти.

    \item \text{Разреженность}. На сильно разреженных матрицах преимущество CSparse становится более заметным, так как оптимизированные алгоритмы позволяют эффективно пропускать нулевые элементы.
\end{itemize}

\subsection{Выводы по экспериментам}

\begin{itemize}
    \item На идентичных данных реализация CSparse показывает значительно меньшее время выполнения операций по сравнению с самостоятельной реализацией COO. Разница варьируется от 20 до 300 раз в зависимости от размера и разреженности матрицы.
    \item Императивная реализация на C с форматом COO проста в реализации и понимании, но уступает оптимизированной библиотеке CSparse в производительности.
    \item CSparse использует эффективные алгоритмы и структуры данных, что делает его предпочтительным выбором для задач, критичных к производительности.
    \item Плоские форматы хранения (COO) обеспечивают простоту реализации, но требуют дополнительных преобразований для эффективных вычислений.
\end{itemize}

\section{Заключение}

В ходе выполнения работы получены следующие результаты.

\begin{itemize}
    \item Реализована библиотека разреженной линейной алгебры на языке C в формате COO с операцией умножения матриц.
    \item Проведено сравнительное измерение производительности с использованием эталонной библиотеки CSparse (SuiteSparse) на реальных матрицах из коллекции SuiteSparse Matrix Collection.
    \item Продемонстрированы различные компромиссы подходов. Самостоятельная реализация на C с форматом COO обеспечивает простоту и наглядность кода, но уступает в производительности оптимизированной библиотеке CSparse. CSparse использует эффективный формат CSC и оптимизированные алгоритмы, что обеспечивает ускорение от 20 до 300 раз.
    \item Выявлено, что преимущество CSparse наиболее заметно на сильно разреженных матрицах, где оптимизированные алгоритмы позволяют эффективно пропускать нулевые элементы.
    \item Собственная реализация COO предпочтительна для учебных целей, прототипирования и задач, где простота реализации важнее абсолютной производительности. CSparse рекомендуется для production-систем, требующих максимальной производительности.
\end{itemize}
