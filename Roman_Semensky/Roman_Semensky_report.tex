\section{Введение}

Разреженные матрицы, где большинство элементов нулевые, возникают в задачах вычислительной математики, анализа графов и машинного обучения. Хранение таких матриц в полном виде неэффективно, поэтому разработаны специализированные форматы и библиотеки для работы с ними.

\section{Цель работы}

\text{Целью работы является} анализ компромиссов между двумя подходами к хранению и обработке разреженных матриц: самостоятельной императивной реализацией на языке C с форматом COO (Coordinate List) и эталонной библиотекой CSparse (SuiteSparse), реализованной на языке C с использованием формата CSC (Compressed Sparse Column).

\section{Обзор}

Разреженные матрицы могут храниться в различных форматах. Формат COO (Coordinate List) представляет матрицу тремя плоскими массивами: индексы строк, индексы столбцов и значения ненулевых элементов. Альтернативный подход представлен в библиотеке CSparse (часть SuiteSparse), где используется формат CSC (Compressed Sparse Column), обеспечивающий более эффективный доступ к столбцам матрицы.

\section{Описание предлагаемого решения}

Сравнение проводилось между двумя подходами к представлению разреженных матриц.

\begin{itemize}
    \item{Собственная реализация (COO Format)}. Реализация на языке C, использующая формат Coordinate List (COO) с тремя плоскими массивами (индексы строк, индексы столбцов, значения). Управление памятью осуществляется вручную через \texttt{malloc}/\texttt{free}. Умножение матриц и матриц на векторы реализовано через вложенные циклы с линейным поиском для суммирования элементов.

    \item{CSparse (SuiteSparse)}. Использование эталонной библиотеки CSparse, применяемой без модификаций. Библиотека использует формат CSC и оптимизированные алгоритмы умножения матриц.
\end{itemize}

\section{Эксперименты}

\subsection{Методика измерений}

\begin{itemize}
    \item \text{Были использованы} реальные матрицы из коллекции SuiteSparse Matrix Collection: \texttt{dolphins} (62×62, 159 ненулевых элементов), \texttt{lesmis} (77×77, 254 ненулевых), \texttt{polbooks} (105×105, 441 ненулевых), \texttt{football} (115×115, 613 ненулевых), \texttt{celegansneural} (297×297, 2345 ненулевых), \texttt{netscience} (1589×1589, 2742 ненулевых). Все матрицы являются квадратными и симметричными.
    \item \text{Рассматривались} операции умножения матрицы на саму себя ($A \times A$) и умножения матрицы на вектор ($A \times x$).
    \item \text{Инструменты измерения}. POSIX-таймер \texttt{clock()} из библиотеки \texttt{<time.h>} с точностью до микросекунд. Для каждой матрицы выполнялся один запуск.
\end{itemize}

\subsection{Анализ результатов}

Разница в производительности обусловлена несколькими факторами.

\begin{itemize}
    \item \text{Особенности реализации алгоритмов}. При умножении матриц в COO сначала выполняется предварительная сортировка элементов квадратичным методом (сортировка выбором), что само по себе требует много времени. Затем происходит полный перебор всех пар ненулевых элементов обеих матриц. Для каждого совпадения индексов выполняется линейный поиск по уже накопленному массиву результата, чтобы проверить, не добавлялся ли уже элемент с такими координатами (для суммирования значений). По мере заполнения результата время этого поиска постоянно растёт. CSparse использует специализированные алгоритмы, полностью избегающие подобных линейных поисков.

    \item \text{Лишние преобразования данных}. При умножении матрицы на вектор в COO разреженный вектор сначала разворачивается в плотный массив (занимающий память по размеру всей размерности матрицы), затем создаётся ещё один плотный временный массив для накопления результата, и в конце он снова упаковывается обратно в разреженный формат COO. Эти многократные преобразования и дополнительные проходы по данным создают существенные накладные расходы.

    \item \text{Структура данных}. Формат CSC в CSparse хранит указатели на начало каждого столбца, что позволяет мгновенно получать доступ ко всем элементам нужного столбца, что критически важно для умножения. В формате COO элементы одного столбца разбросаны по массиву, поэтому для доступа к ним требуется постоянный перебор.

    \item \text{Управление памятью}. Реализация COO выполняет множественные выделения и освобождения памяти (создание временных массивов максимального размера, плотных векторов, копирование результатов), что создаёт дополнительные накладные расходы. CSparse использует более эффективные стратегии работы с памятью.

    \item \text{Разреженность}. На сильно разреженных матрицах преимущество CSparse становится более заметным, так как оптимизированные алгоритмы позволяют эффективно пропускать нулевые элементы, тогда как в COO накладные расходы на сортировку и поиск становятся доминирующими.

    \item \text{Тип операции}. Для умножения матрицы на вектор разница в производительности менее выражена (от 2 до 8 раз), так как сама операция проще: не требуется перебор пар элементов и поиск дубликатов. Основная задержка в COO здесь связана именно с накладными расходами на преобразование форматов и выделение лишней памяти, а не с тяжелыми вычислениями.
\end{itemize}

\subsection{Выводы по экспериментам}

\begin{itemize}
    \item На идентичных данных реализация CSparse показывает значительно меньшее время выполнения операций по сравнению с самостоятельной реализацией COO. Для умножения матриц разница варьируется от 18 до 817 раз, а для умножения матрицы на вектор — от 2 до 8 раз в зависимости от размера и разреженности матрицы.
    \item Императивная реализация на C с форматом COO проста в реализации и понимании, но уступает оптимизированной библиотеке CSparse в производительности.
    \item CSparse использует эффективные алгоритмы и структуры данных, что делает его предпочтительным выбором для задач, критичных к производительности.
    \item Плоские форматы хранения (COO) обеспечивают простоту реализации, но работают медленнее.
\end{itemize}

\section{Заключение}

В ходе выполнения работы получены следующие результаты.

\begin{itemize}
    \item Реализована библиотека разреженной линейной алгебры на языке C в формате COO с операциями умножения матриц и умножения матрицы на вектор.
    \item Проведено сравнительное измерение производительности с использованием эталонной библиотеки CSparse (SuiteSparse) на реальных матрицах из коллекции SuiteSparse Matrix Collection.
    \item Продемонстрированы различные компромиссы подходов. Самостоятельная реализация на C с форматом COO обеспечивает простоту и наглядность кода, но уступает в производительности оптимизированной библиотеке CSparse. CSparse использует эффективный формат CSC и оптимизированные алгоритмы, что обеспечивает значительное ускорение для обеих операций, особенно заметное при умножении матриц на больших и разреженных данных.
    \item Выявлено, что преимущество CSparse наиболее заметно на сильно разреженных матрицах и при более сложных операциях (умножение матриц), где оптимизированные алгоритмы позволяют эффективно пропускать нулевые элементы и минимизировать накладные расходы.
    \item Собственная реализация COO предпочтительна для учебных целей, прототипирования и задач, где простота реализации важнее абсолютной производительности. CSparse рекомендуется для production-систем, требующих максимальной производительности.
\end{itemize}
