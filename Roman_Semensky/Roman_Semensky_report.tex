\section{Введение}
Работа выполнялась в рамках учебной практики второго семестра первого курса на кафедре системного программирования. Разреженные матрицы, в которых большинство элементов равны нулю, широко применяются в вычислительной математике, анализе графов и машинном обучении. Хранение таких матриц в плотном виде приводит к нерациональному использованию памяти и вычислительных ресурсов. Для работы с ними разработаны специализированные форматы хранения, такие как COO (Coordinate List) и CSC (Compressed Sparse Column), а также оптимизированные библиотеки, например CSparse, входящая в состав SuiteSparse.

\section{Цель работы}
Целью работы является сравнительный анализ производительности двух подходов к хранению и обработке разреженных матриц:
\begin{itemize}
    \item самостоятельной реализации на языке~C с использованием оптимизированного формата COO;
    \item эталонной библиотеки CSparse (SuiteSparse), использующей формат CSC.
\end{itemize}

\section{Задачи работы}
Для достижения поставленной цели были определены следующие задачи:
\begin{enumerate}
    \item реализовать библиотеку для работы с разреженными матрицами в формате COO, включающую операции умножения матриц и умножения матрицы на вектор с минимизацией алгоритмической сложности;
    \item подготовить набор тестовых матриц из открытой коллекции SuiteSparse Matrix Collection;
    \item разработать программу для измерения времени выполнения операций для обеих реализаций;
    \item провести сравнительные измерения производительности и проанализировать полученные результаты;
    \item сформулировать выводы о применимости каждого подхода в зависимости от требований к производительности.
\end{enumerate}

\section{Обзор форматов хранения разреженных матриц}
Разреженные матрицы могут храниться в различных форматах. Формат COO представляет матрицу тремя одномерными массивами: индексы строк, индексы столбцов и значения ненулевых элементов. Данный формат интуитивно понятен и прост в модификации (добавлении новых элементов).

Альтернативный подход представлен в библиотеке CSparse, где используется формат CSC. В этом формате ненулевые элементы хранятся упорядоченно по столбцам с использованием дополнительного массива указателей на начала столбцов. Это обеспечивает быстрый доступ к элементам конкретного столбца и высокую пространственную локальность данных при обходе.

\section{Описание решения}
Сравнение проводилось между двумя подходами к представлению разреженных матриц.

\subsection{Собственная реализация (формат COO)}
Реализация на языке~C использует формат COO. При проектировании алгоритмов особое внимание было уделено минимизации вычислительных накладных расходов, характерных для наивных реализаций:
\begin{itemize}
    \item \textbf{Сортировка:} для упорядочивания данных перед операциями используется стандартная быстрая сортировка \texttt{qsort} со временной сложностью $O(N \log N)$, что критически важно для сохранения производительности на больших матрицах.
    \item \textbf{Устранение линейного поиска:} при умножении матриц вместо поиска дубликатов в результирующем массиве применяется буфер строки (временный плотный массив размером с количество столбцов). Это обеспечивает прямую адресацию и накопление результатов за время $O(1)$ на элемент, выступая в роли идеального хеш-словаря с прямым доступом по индексу столбца и полностью устраняя квадратичную сложность.
    \item \textbf{Оптимизация работы с векторами:} интерфейс умножения матрицы на вектор реализован с использованием стандартных плотных массивов (\texttt{float*}) для входных и выходных данных. Это полностью исключает накладные расходы на многократную упаковку и распаковку разреженных векторов, соответствуя лучшим практикам разработки.
\end{itemize}
Такой подход сохраняет простоту формата COO, но сводит его алгоритмические недостатки к минимуму.

\subsection{Библиотека CSparse}
Использование эталонной библиотеки CSparse осуществлялось без модификаций. Библиотека использует формат CSC и оптимизированные алгоритмы умножения, которые минимизируют количество операций с памятью и переборов элементов за счёт эффективной структуры данных.

\section{Эксперименты}

\subsection{Методика измерений}
Для проведения сравнительного анализа были использованы реальные матрицы из открытой коллекции SuiteSparse Matrix Collection: \texttt{dolphins} ($62 \times 62$, 159 ненулевых элементов), \texttt{lesmis} ($77 \times 77$, 254 ненулевых), \texttt{polbooks} ($105 \times 105$, 441 ненулевых), \texttt{football} ($115 \times 115$, 613 ненулевых), \texttt{celegansneural} ($297 \times 297$, 2345 ненулевых), \texttt{netscience} ($1589 \times 1589$, 2742 ненулевых). Все матрицы являются квадратными и симметричными.

Рассматривались две операции:
\begin{itemize}
    \item умножение матрицы на саму себя ($A \times A$);
    \item умножение матрицы на вектор ($A \times x$).
\end{itemize}

Измерения времени выполнялись с использованием стандартной функции \texttt{clock()} из библиотеки \texttt{<time.h>}.

Характеристики вычислительной системы:
\begin{itemize}
    \item операционная система: Ubuntu~24.04 LTS;
    \item ядро: Linux~6.17.0-35-generic (x86\_64);
    \item процессор: 13th~Gen Intel Core i5-13420H (12~ядер, частота до 4,6~ГГц);
    \item оперативная память: 16~ГБ;
    \item компилятор: GCC (GNU Compiler Collection, стандартные флаги оптимизации \texttt{-O2}).
\end{itemize}

\subsubsection{Анализ результатов}
Разница в производительности обусловлена следующими факторами:
\begin{itemize}
    \item \textbf{Структура данных и локальность кэша:} Библиотека CSparse использует формат \textbf{CSC (Compressed Sparse Column)}. В этом формате элементы хранятся по столбцам с использованием массива указателей на начала столбцов. Это обеспечивает последовательный доступ к памяти и позволяет выполнять умножение за один проход. Применение CSC в собственной реализации не входило в задачи работы, так как целью было оценить и исчерпать потенциал оптимизации именно формата COO.
    \item \textbf{Алгоритмическая сложность:} Даже при использовании сортировки за $O(N \log N)$ и буфера строки для устранения линейного поиска, формат COO всё ещё требует выделения временной памяти и косвенного доступа к индексам, что создает б\'{о}льшие накладные расходы по сравнению со специализированными библиотечными решениями, особенно на матрицах с большим количеством ненулевых элементов (например, \texttt{netscience}).
    \item \textbf{Оптимизация интерфейса:} Разница при умножении на вектор минимальна (2--6 раз), так как в текущей реализации исключены накладные расходы на конвертацию векторов, и операция сводится к простому проходу по ненулевым элементам с прямой записью в плотный массив результата.
\end{itemize}

\subsubsection{Выводы по экспериментам}
На основе проведённых измерений можно сделать следующие выводы:
\begin{itemize}
    \item Несмотря на оптимизации, библиотека CSparse показывает меньшее время выполнения: для умножения матриц ускорение составляет от 3,636 до 64,881 раз, для умножения матрицы на вектор~--- от 2,000 до 6,125 раз.
    \item Наиболее значительное преимущество CSparse наблюдается на больших разреженных матрицах (\texttt{netscience}), где критически важны эффективное использование кэша процессора и отсутствие выделения временных буферов.
    \item Формат COO остается отличным выбором для этапа конструирования и модификации матрицы благодаря простоте добавления элементов, но для интенсивных вычислительных операций предпочтительнее использовать специализированные форматы, такие как CSC и CSR (Compressed Sparse Row), и оптимизированные библиотеки.
\end{itemize}

\section{Заключение}
В ходе выполнения работы были получены следующие результаты:
\begin{itemize}
    \item реализована библиотека разреженной линейной алгебры на языке~C в формате COO с операциями умножения матриц и умножения матрицы на вектор, в которой с самого начала были применены алгоритмические оптимизации для минимизации вычислительной сложности;
    \item проведено сравнительное измерение производительности с использованием эталонной библиотеки CSparse на реальных матрицах из коллекции SuiteSparse Matrix Collection;
    \item продемонстрированы компромиссы между двумя подходами: самостоятельная реализация обеспечивает простоту и наглядность кода, но уступает в производительности оптимизированной библиотеке из-за различий в организации памяти и структуре данных;
    \item выявлено, что преимущество CSparse наиболее заметно при более сложных операциях, таких как умножение матриц на больших размерах задач, где ускорение достигает десятков раз.
\end{itemize}
